# 1.0.6 通知与话题识别修复

## 现场证据

通知历史中的只读审查来自 subagent 独立会话；原桌面监控接受 user 和 subagent 的 task_complete，因此过程审查被当成任务结束。标题提取没有验证 message.role，误将 developer 的 skills_instructions、工具变更说明作为标题。主会话日志还出现文件名 ID 与 session_meta.id 不同的情形，按文件名建立话题会拆分同一真实对话。

## 行为

- 桌面通知仅接受 user 主会话，子代理不建话题、不发完成通知。
- session_meta.id 优先于文件名；启动扫描和增量读取都初始化身份。
- 同一真实主会话复用现有话题；旧文件名别名有本群话题、真实 ID 没有时沿用旧根消息。有真实 ID 话题时优先保留它。旧回复消息映射和默认绑定在内存中归一，后续配置保存会持久化。不删除旧飞书消息。
- 仅从 user 消息中提取请求标题，并过滤内部上下文；官方对话名优先。
- 后台完成事件缺少最终文本和结果附件时不使用过程输出冒充最终结果。

## 验证

node --test tests/*.test.mjs；日志回放覆盖子代理完成、commentary、developer 注入、主会话完成、文件名与真实 ID 不同、重复读取、旧话题沿用和真实话题优先。无外部飞书测试消息、无历史消息补发或删除。

## 范围

已有错误话题的飞书标题不会自动改名或清理。正常主对话每轮最终答复仍会通知；“已完成”指该轮结束，不代表整个项目全部结束。
